# 채점 기준

**학습자가 답하기 전에 이 내용을 인용하거나 힌트로 쓰지 않는다.** 예측 질문을 낸 뒤, 학습자의 답을 채점할 때만 참고한다.

## 02-L05: 아이템 10만 개의 GC 마킹 비용 (2026-11-01 실측으로 수정)

- 실측 순서 (Mono·IL2CPP, 10만·100만 개 공통): **0 기준선 ≈ 2 `struct[]` < 1 `List<class>` < 3a 참조 필드 `struct[]` + 공유 문자열 < 3b 원소마다 문자열**. IL2CPP 100만 개: 0.31 / 0.33 / 2.47 / 4.10 / 4.92 ms. 상세는 [02-L05 README](../Assets/Labs/02_GC/L05_MarkCost/README.md)
- **설계2는 기준선과 같다.** 참조 필드가 없는 struct 배열은 `GC_MALLOC_ATOMIC`으로 할당되어 마크 비트만 세우고 내용을 읽지 않는다. 크기와 무관.
- **설계3은 공유 문자열이어도 설계1보다 비싸다.** 원소 비트맵 디스크립터(`GC_gcj_vector_malloc`)로 원소(24 B)마다 훑어서, 100만 개면 24 MB를 읽는다. 설계1은 8 B 포인터만 든 8 MB 배열을 기본 루프로 훑고, 원소 객체는 참조 필드가 없어 atomic이므로 마크 비트만 세운다.
- 수정 전 기준("설계2 < 설계3 ≤ 설계1", "공유 문자열이면 설계3이 훨씬 싸짐")은 실측과 다르다. 방문 객체 수만 세고 훑는 바이트와 스캔 방식을 빠뜨렸다.
- 핵심 포인트: "참조 필드 하나가 배열 전체를 GC 스캔 대상으로 만든다", "비용 ≈ 훑는 바이트 × 스캔 방식의 단가 + 새로 표시하는 객체 수".
